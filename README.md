<a id="overview"></a>
## 프로젝트 한눈에 보기

> 이 프로젝트는 단순한 클론 코딩 결과물이 아니라,  
> **강의를 출발점으로 삼아 실제 공홈을 분석하고 직접 구조를 수정·확장하며 발전시켜온 프로젝트**입니다.

### 핵심 요약

- **출발점**: 스타벅스 스타일 클론 코딩 강의 기반 제작
- **문제 인식**: 강의 UI가 실제 공홈과 달라 이질감이 존재
- **개선 과정**: 공홈을 직접 디버깅하고 레이아웃과 퍼블리싱을 재구현
- **확장 경험**: 강의 범위를 넘어 기능과 UI를 직접 추가
- **현재 목표**: 브랜드 중심 UI 재현을 넘어 **모바일 중심 실사용 UX 개선**으로 확장

<a id="about"></a>
## 프로젝트 소개

이 프로젝트는 퍼블리싱 영역의 기본기와 실무와 유사한 화면 구현 경험을 쌓기 위해  
스타벅스 스타일의 사이트를 **클론 코딩 강의**를 기반으로 제작한 프로젝트입니다.

다만 제작 당시 강의에서 다루는 사이트 UI는 이미 몇 년 전 기준의 스타벅스 공홈 구조와 디자인을 바탕으로 한 내용이었기 때문에,  
실제 공식 홈페이지와 비교했을 때 **레이아웃과 UI에서 차이와 이질감**이 존재했습니다.

그래서 단순히 강의 내용을 그대로 따라가는 데서 멈추지 않고,  
코드 작성 규칙과 문법을 다시 학습하면서 실제 스타벅스 공홈을 직접 디버깅하고 분석하여  
**공홈의 레이아웃과 더 유사한 형태로 퍼블리싱을 직접 재구현**했습니다.

또한 이 과정에서 강의 범위를 넘어 다음과 같은 경험까지 함께 쌓을 수 있었습니다.

- 기존 코드의 수정과 확장을 통한 **유지보수 경험**
- Git과 브랜치 흐름을 배우며 작업 내역을 관리하는 **버전 관리 경험**
- 강의에 없던 기능과 퍼블리싱 요소를 직접 추가하는 **확장 경험**

즉, 이 프로젝트는 단순한 강의 결과물이 아니라,  
**강의를 출발점으로 삼아 직접 구조를 손보고 기능을 확장하며 발전시켜온 프로젝트**입니다.

<a id="history"></a>
## 프로젝트 히스토리

| 단계 | 설명 |
|---|---|
| **1. 강의 기반 제작** | 퍼블리싱 기본기와 실무형 화면 구현 감각을 익히기 위해 시작 |
| **2. 공홈과 차이 인식** | 강의 UI와 실제 스타벅스 공홈 간 레이아웃 및 시각적 차이를 발견 |
| **3. 직접 디버깅 및 재구현** | 공홈 구조를 분석하고 레이아웃과 퍼블리싱을 직접 수정 |
| **4. 기능 및 UI 확장** | 강의에 없는 기능과 퍼블리싱 요소를 추가하며 프로젝트 확장 |
| **5. 현재 리뉴얼 단계** | 브랜드 중심 UI 재현을 넘어 모바일 중심 UX 개선 방향으로 재정의 |

<a id="current-status"></a>
## 현재 상태

현재 `master` 브랜치는 **기존 공개 기준이자 프로덕션 기준 브랜치**입니다.

이 브랜치는 다음과 같은 의미를 가집니다.

- 강의를 통해 처음 제작했던 **초기 버전의 흐름**
- 공홈과의 차이를 줄이기 위해 직접 수정하고 개선한 **퍼블리싱 결과**
- 강의 범위를 넘어 새 기능과 UI를 추가하며 확장했던 **작업 이력**
- 앞으로의 리뉴얼 방향을 정리하기 전까지의 **기존 기준점**

### 현재 보완이 필요한 지점

- 반응형 대응이 충분히 정리되어 있지 않음
- 모바일 환경에서 행동형 CTA 우선순위가 부족함
- 브랜드 중심 화면 재현에는 집중되어 있으나, 실사용 흐름 중심 UX 개선은 더 필요함
- 브랜치 목적과 실제 작업 범위가 명확히 정리되지 않았던 흔적이 있음

즉, 이 프로젝트는 퍼블리싱 결과물로서의 의미는 충분하지만,  
이제는 **실제 서비스 사용자 경험을 고려한 방향으로 한 단계 더 나아갈 필요가 있는 상태**입니다.

<a id="why-renewal"></a>
## 왜 이 프로젝트를 리뉴얼하는가

이 프로젝트를 다시 손보려는 이유는 단순히 “예전 작업물”이기 때문이 아닙니다.

오히려 이 프로젝트는 퍼블리싱 기본기를 쌓고,  
강의 기반 결과물을 내 방식으로 수정하고 확장해본 흔적이 남아 있는 **고유한 프로젝트**이기 때문에  
그 흐름을 보존하면서도 한 단계 더 발전시킬 가치가 있다고 판단했습니다.

### 1. 강의 기반 출발점에서 직접 개선해온 프로젝트이기 때문

이 프로젝트는 처음부터 완전히 독립적으로 시작한 프로젝트는 아니지만,  
실제 작업 과정에서는 강의 내용을 그대로 유지하지 않았습니다.

당시 강의의 UI는 실제 공홈과 차이가 있었고,  
그 차이를 줄이기 위해 직접 공홈을 디버깅하고 레이아웃을 다시 구현했습니다.  
또한 강의에서 다루지 않은 기능과 퍼블리싱 요소를 직접 추가하면서  
프로젝트를 내 방식대로 확장해왔습니다.

즉, 이 프로젝트는 단순 학습 결과물이 아니라  
**학습한 내용을 기반으로 실제 화면을 다시 해석하고 개선한 경험이 축적된 작업물**입니다.

### 2. 이제는 브랜드 중심 UI 재현을 넘어서고 싶기 때문

기존까지의 개선은 주로 **공홈과 더 유사한 UI를 구현하는 것**에 가까웠습니다.  
하지만 지금은 그 단계에서 더 나아가고자 합니다.

이제는 단순히 브랜드 사이트처럼 보이게 만드는 것보다,

- 실제 서비스 사용자가 모바일 환경에서 어떤 행동을 먼저 하게 되는지
- 어떤 CTA가 더 우선되어야 하는지
- 웹과 앱이 어떤 방식으로 연결되어야 자연스러운지

까지 고민하는 방향으로 가고자 합니다.

특히 스타벅스와 같이 **웹과 앱이 함께 존재하는 서비스 구조**에서는  
모바일 웹에서 앱으로 자연스럽게 이어질 수 있는 흐름이 중요하다고 생각합니다.

앱 설치 유도나 `앱에서 열기`, `웹에서 계속하기`와 같은 선택 기반 UX를 통해  
사용자가 강제되지 않으면서도 더 적절한 환경으로 이동할 수 있게 하는 구조는  
실제 서비스 경험 측면에서도 충분히 개선 가치가 있다고 판단했습니다.

> 이번 리뉴얼의 핵심은  
> **브랜드 중심 UI 구현에 국한되지 않고, 실서비스 사용자 경험을 기반으로 모바일 중심으로 개선하는 것**입니다.

### 3. 초기 버전과 개선 버전을 분리해 보존하고 싶기 때문

이 프로젝트는 강의를 통해 배웠던 초기 버전과,  
그 이후 직접 수정하고 확장하며 개선했던 버전,  
그리고 앞으로의 리뉴얼 방향까지 모두 의미가 있습니다.

그래서 기존 작업 흔적을 무조건 덮어쓰기보다,  
**초기 흐름과 개선된 결과물을 분리해서 보존**하고  
이후 작업은 새로운 기준 브랜치를 통해 더 명확하게 관리하려고 합니다.

<a id="pros-cons"></a>
## 스타벅스 공홈을 참고하며 본 장단점

### 장점

- 브랜드 아이덴티티와 비주얼 톤앤매너가 명확함
- 시즌 프로모션, 리워드, 배너 등 마케팅 요소가 강하게 드러남
- 메인 페이지에서 브랜드 경험 자체를 강조하는 구조가 인상적임

### 아쉬운 점

- 모바일에서는 브랜드 비주얼보다 **즉시 행동**이 더 중요할 수 있음
- 사용자가 원하는 기능까지 도달하기 위한 흐름이 다소 길게 느껴질 수 있음
- `자세히 보기`와 같은 추상적인 CTA보다 **매장 찾기, 주문, 리워드 확인** 같은 행동형 CTA가 더 우선될 수 있음
- 스타벅스와 같이 웹과 앱이 함께 운영되는 서비스 구조에서는, 모바일 웹에서 앱으로 자연스럽게 이어지는 전환 흐름이 상대적으로 약하게 느껴질 수 있음
- 앱 설치 여부와 관계없이 사용자가 `앱에서 열기`, `웹에서 계속하기` 중 하나를 자연스럽게 선택할 수 있는 UX가 보완된다면 모바일 웹 경험도 더 개선될 수 있음

이 프로젝트는 이러한 문제 인식을 바탕으로,  
**모바일 사용자의 실제 행동 흐름에 맞는 구조로 재해석**하는 것을 목표로 합니다.

<a id="future-plan"></a>
## 앞으로의 개발 방향

이 프로젝트는 앞으로 단순한 UI 복제형 클론이 아니라,  
**모바일 접근성 우선 브랜드 리뉴얼 프로젝트**로 재정의하여 개선할 예정입니다.

### 1. 모바일 접근성 우선 구조로 전환

- 데스크톱 중심 구조보다 모바일 사용자 흐름 우선
- 빠르게 원하는 행동으로 이동할 수 있는 구조 설계
- 터치 영역, 정보 밀도, 버튼 우선순위, 가독성 개선

### 2. Hero 영역 CTA 재구성

기존의 `자세히 보기` 중심 구조에서 벗어나  
모바일에서는 아래와 같은 행동형 CTA를 우선적으로 검토합니다.

- 내 주변 매장 찾기
- 앱에서 주문하기
- 리저브 매장 찾기

### 3. Web-to-App CTA UX 도입

스타벅스와 같이 웹과 앱을 함께 운영하는 브랜드 서비스는  
모바일 환경에서 웹과 앱의 역할이 명확히 나뉠 수 있습니다.

따라서 모바일 웹에서는 단순 정보 제공을 넘어,  
사용자가 상황에 따라 앱으로 자연스럽게 이동하거나 웹에서 계속 탐색할 수 있도록  
**선택 기반의 CTA 흐름**을 제공하는 것이 중요하다고 판단했습니다.

#### 예상 구현 방향

- 앱에서 열기
- 웹에서 계속하기
- iOS / Android 환경별 스토어 유도
- 사용자 선택 기반 CTA 제어
- 행동형 CTA와 연계한 모바일 전환 UX 개선

### 4. 반응형 레이아웃 재정비

단순히 화면을 줄이는 수준이 아니라,  
모바일과 데스크톱에서 정보 우선순위가 다를 수 있다는 전제로  
**레이아웃 자체를 다시 설계**할 예정입니다.

<a id="branch-strategy"></a>
## 브랜치 전략

기존에는 작업 흐름이 누적되면서  
브랜치 목적과 실제 작업 범위가 명확하지 않은 부분이 있었습니다.

앞으로는 역할을 더 분명히 나누는 방식으로 브랜치 전략을 정리합니다.

### 브랜치 역할

| 브랜치 | 역할 |
|---|---|
| `master` | 현재 공개 및 프로덕션 기준 브랜치, 기존 결과물과 개선 이력 보존 |
| `dev` | 앞으로의 통합 개발 기준 브랜치, 모바일 접근성 우선 리뉴얼 중심 브랜치 |
| `feature/*` | 기능 단위 브랜치, 하나의 목적 또는 기능에 집중하여 작업 |

### 예상 feature 브랜치 예시

- `feature/header-responsive`

<a id="master-role"></a>
## `master` 브랜치의 역할

현재 `master` 브랜치는 아래 역할을 담당합니다.

- 기존 프로덕션 결과물 보존
- 강의 기반 초기 버전과 이후 직접 개선한 작업 이력 보존
- 현재 프로젝트 상태 문서화
- 왜 리뉴얼이 필요한지 설명하는 기준점 유지

즉, `master`는 앞으로의 모든 개발이 이루어지는 브랜치라기보다  
**이 프로젝트가 어떻게 시작되었고, 어떻게 수정되었으며, 왜 다음 단계로 가려는지를 보여주는 기준 브랜치**입니다.

---

<a id="dev-transition"></a>
## 개발 기준 브랜치 전환 예정

향후 실제 개발 기준 브랜치는 `dev`로 전환할 예정입니다.

### 예정 작업 흐름

- `feature/*` → `dev`
- 충분히 안정화된 시점에 `dev` → `master`

이를 통해 기존 결과물과 새로운 리뉴얼 작업을 분리하고,  
초기 버전과 개선 버전, 그리고 앞으로의 결과물을 더 명확하게 관리하려고 합니다.

<a id="summary"></a>
## 정리

이 프로젝트는 강의를 통해 시작했지만,  
실제 공홈과의 차이를 직접 분석하고 수정하며  
강의 범위를 넘어 새로운 기능과 퍼블리싱을 추가해온 프로젝트입니다.

그리고 이제는 그 흐름을 기반으로,  
브랜드 중심 UI 재현에 머무르지 않고  
**실제 실서비스 사용자 경험을 고려한 모바일 중심 리뉴얼 프로젝트**로 한 단계 더 발전시키고자 합니다.

현재 `master` 브랜치는 그 시작점과 개선 과정을 보존하는 브랜치이며,  
앞으로의 실제 리뉴얼 작업은 `dev` 브랜치를 중심으로 이어질 예정입니다.
