# Starbucks App Renewal 링크 정책 명세서

## 1. 개요

이 문서는 Starbucks App Renewal 포트폴리오 프로젝트의 링크 및 인터랙션 요소 사용 기준을 정의한다.

이 프로젝트는 HTML, CSS, JavaScript 기반의 정적 퍼블리싱 포트폴리오이며, 실제 스타벅스 서비스 전체를 운영하기 위한 사이트가 아니다. 따라서 모든 메뉴와 푸터 항목을 실제 스타벅스 사이트처럼 완전하게 연결하는 것이 목적이 아니다.

이 문서의 목적은 포트폴리오 범위 안에서 다음 상태를 명확하게 구분하는 것이다.

- 실제 페이지나 외부 URL로 이동하는 요소
- 현재 화면의 상태를 변경하는 요소
- 아직 구현되지 않았거나 포트폴리오 범위 밖에 있는 요소

링크 정책을 명확히 정리하면 평가자가 프로젝트의 의도를 쉽게 이해할 수 있고, 키보드 사용자와 스크린리더 사용자에게도 예측 가능한 탐색 경험을 제공할 수 있다. 또한 추후 내부 페이지가 추가될 때 어떤 항목을 실제 링크로 전환해야 하는지 일관된 기준을 유지할 수 있다.

이 프로젝트의 기본 방향은 다음과 같다.

- 실제 이동은 `a` 태그를 사용한다.
- 화면 상태 변경은 `button`을 사용한다.
- 아직 동작하지 않는 항목은 가짜 링크로 두지 않는다.
- `javascript:void(0)`는 정책상 사용하지 않는다.
- 외부 스타벅스 링크는 핵심 CTA 중심으로 제한한다.
- `index.html`과 `signup/index.html`에 동일한 기준을 적용한다.
- 탭 이동 대상은 실제로 의미 있는 요소만 남긴다.

## 2. 링크 정책 핵심 원칙

모든 인터랙션 요소는 마크업을 선택하기 전에 먼저 목적에 따라 분류한다.

| 목적 | 사용 요소 | 예시 |
| --- | --- | --- |
| 다른 페이지나 URL로 이동 | `a` | 내부 페이지, 스타벅스 공식 페이지 |
| 같은 페이지 안에서 특정 위치로 이동 | 유효한 해시를 가진 `a` | 본문 바로가기, 섹션 이동 |
| 화면 상태 변경 | `button` | 메뉴 토글, 모달 열기, 슬라이드 이동 |
| 폼 제출 | `button type="submit"` | 로그인 제출 버튼 |
| 아직 미구현 | 텍스트 또는 비활성 상태 요소 | 준비 중인 메뉴, 푸터 항목 |

이 프로젝트의 정책은 모든 시각적 메뉴를 클릭 가능하게 만드는 것이 아니다. 클릭 가능한 요소가 있다면 그 요소가 실제로 무엇을 하는지 정직하게 표현하는 것이 핵심이다.

## 3. `a` 태그 사용 기준

`a` 태그는 사용자를 다른 목적지로 이동시키는 경우에만 사용한다.

### 내부 링크

프로젝트 내부 페이지로 이동할 때 `a` 태그를 사용한다.

예시:

- 메인 페이지
- 로그인 페이지
- 추후 추가될 상세 페이지
- 추후 추가될 정책 페이지
- 추후 추가될 메뉴, 매장, 리워드 관련 페이지

내부 링크는 상대 경로를 일관되게 사용한다. 새로운 내부 페이지가 추가될 때는 해당 페이지와 직접 연결되는 메뉴 또는 CTA만 실제 링크로 전환한다.

### 외부 링크

포트폴리오 흐름을 보완하는 일부 스타벅스 공식 페이지로 이동할 때 `a` 태그를 사용한다.

외부 링크로 유지할 수 있는 예시는 다음과 같다.

- 매장 찾기
- 메뉴 보기
- 프로모션 상세 보기
- 리저브 매장 보기
- 리워드 소개 보기

다만 GNB, 푸터, 정책, 소셜 링크 전체를 실제 스타벅스 사이트로 연결할 필요는 없다. 포트폴리오의 목적은 실서비스 전체 연결이 아니라 퍼블리싱 구조와 인터랙션 의도를 보여주는 것이다.

### 앵커 링크

같은 페이지 안의 특정 위치로 이동할 때는 실제로 존재하는 `id`를 대상으로 하는 해시 링크를 사용한다.

허용되는 경우:

- skip link
- 본문 바로가기
- 특정 섹션 이동

`href="#"`는 목적지가 불명확하므로 원칙적으로 사용하지 않는다. 페이지 최상단 이동이 명확한 의도인 경우에만 제한적으로 사용할 수 있다.

### `a`를 쓰면 안 되는 경우

다음 경우에는 `a` 태그를 사용하지 않는다.

- 메뉴 열기/닫기
- 모달 열기/닫기
- 프로모션 영역 펼침/접힘
- 슬라이드 이전/다음 이동
- 검색어 삭제
- 현재 화면의 상태만 바꾸는 동작
- 아직 연결할 목적지가 없는 미구현 항목

클릭해도 이동하지 않는다면 링크가 아니다.

## 4. `button` 사용 기준

`button`은 현재 페이지 안에서 UI 상태를 변경하는 조작 요소에 사용한다.

### 메뉴 토글

다음 요소는 `button`으로 처리한다.

- 모바일 헤더 메뉴 열기/닫기
- GNB 하위 메뉴 펼치기/접기
- 헤더 패널 닫기

메뉴 버튼은 상태를 나타내기 위해 `aria-expanded`를 사용하고, 제어 대상이 명확할 경우 `aria-controls`를 함께 사용한다.

### 모달 열기/닫기

다음 요소는 `button`으로 처리한다.

- 주문 방식 선택 모달 열기
- 모달 닫기
- 모달 내부 취소 또는 닫기 동작

모달을 여는 버튼은 필요한 경우 현재 열림 상태를 표현해야 한다. 닫기 버튼은 반드시 접근 가능한 이름을 가져야 한다.

### 검색어 삭제

검색어 삭제처럼 입력값이나 화면 상태만 바꾸는 요소는 `button`으로 처리한다.

검색 자체가 구현되어 있지 않다면 검색 UI가 실제 검색 기능인지, 포트폴리오용 시각 데모인지 정책상 구분되어야 한다.

### 슬라이더 버튼

다음 요소는 `button`으로 처리한다.

- 이전 슬라이드
- 다음 슬라이드
- 슬라이드 상태를 변경하는 커스텀 페이지네이션

슬라이더 버튼은 "이전 프로모션 보기", "다음 프로모션 보기"처럼 동작을 설명하는 이름을 가져야 한다.

### submit 버튼

로그인 제출처럼 폼 제출 의도가 있는 경우 `button type="submit"`을 사용한다.

다만 포트폴리오 프로젝트에서 실제 백엔드 제출이 없다면 해당 폼은 데모 폼으로 문서화되어야 한다. 장기적인 정책으로 `action="javascript:void(0)"`에 의존하지 않는다.

## 5. 임시 링크 처리 정책

### `javascript:void(0)` 사용 금지

`javascript:void(0)`는 프로젝트 정책상 사용하지 않는다.

금지 이유:

- 실제 이동하지 않지만 스크린리더에는 링크로 읽힌다.
- 키보드 탭 이동 대상이 불필요하게 늘어난다.
- QA 과정에서 미구현 상태와 오류 상태를 구분하기 어렵다.
- 실제 링크, 추후 연결 예정 링크, 상태 변경 버튼의 구분이 흐려진다.
- 포트폴리오의 시맨틱 완성도를 낮춘다.

### `href="#"` 지양

`href="#"`는 임시 링크로 사용하지 않는다.

허용할 수 있는 경우는 실제 페이지 내 앵커 이동 의도가 있고, 대상 `id`가 존재하며, 이동 동작이 명확히 필요한 경우로 제한한다.

목적지가 없다면 링크로 만들지 않는다.

### 미구현 메뉴 처리 기준

미구현 메뉴는 목적에 따라 다음과 같이 분류한다.

| 항목 유형 | 처리 기준 |
| --- | --- |
| 단순 섹션 제목 | 링크가 아닌 텍스트로 처리 |
| 추후 내부 페이지 연결 예정 | 문서 또는 식별 속성으로 예정 상태 관리 |
| 비활성 항목 | 비활성 상태로 표현하고 필요 시 탭 이동에서 제외 |
| 포트폴리오 구조 확인용 항목 | 실제 목적지가 없으면 비인터랙션 요소로 유지 |

포트폴리오에서 보여주기 위한 메뉴라도 사용자가 클릭할 수 있을 것처럼 보이는데 아무 일도 하지 않는 구조는 피한다.

### 푸터 및 보조 링크 처리 기준

푸터 링크는 정책, 회사 소개, 소셜, 고객 지원 등 많은 항목을 포함한다. 포트폴리오 프로젝트에서는 모든 푸터 항목을 실제 링크로 연결할 필요가 없다.

권장 기준:

- 포트폴리오 핵심 흐름에 필요한 링크만 활성화한다.
- 공식 외부 링크는 데모 목적이 분명한 경우에만 유지한다.
- 나머지는 비인터랙션 항목 또는 추후 연결 예정 항목으로 분류한다.

### 미구현 상태 표현 기준

미구현 상태는 가짜 링크가 아니라 구조와 문서로 표현한다.

사용 가능한 방식:

- 링크가 아닌 텍스트
- 비활성 시각 상태
- 필요한 경우 `aria-disabled`
- 추후 구현 시 `data-link-status="planned"` 같은 식별 속성
- README 또는 docs에 포트폴리오 범위 명시

## 6. 외부 링크 정책

이 프로젝트는 포트폴리오이므로 외부 링크는 제한적으로 사용한다. 너무 많은 외부 링크는 사용자가 포트폴리오 흐름을 벗어나 실제 스타벅스 사이트로 이동하게 만들고, 프로젝트 자체의 완성도를 평가하기 어렵게 만든다.

### 유지할 수 있는 외부 링크

다음처럼 핵심 사용자 흐름을 보완하는 외부 링크는 유지할 수 있다.

- 매장 찾기
- 메뉴 보기
- 프로모션 상세 보기
- 리저브 매장 정보
- 리워드 공식 소개

이 링크들은 프로젝트가 의도하는 서비스 맥락을 설명하는 데 도움을 준다.

### 축소할 외부 링크

다음 항목들은 무조건 외부 사이트로 연결하지 않는다.

- GNB 하위 메뉴 전체
- 푸터 정책 링크 전체
- 회사 소개 링크 전체
- 소셜 링크 전체
- 고객 지원 링크 전체

포트폴리오 범위에서 실제로 보여줄 필요가 있는 링크만 남긴다.

### 새 탭 사용 기준

외부 링크가 포트폴리오 흐름을 중단시킬 수 있다면 새 탭을 사용할 수 있다.

현재 탭 사용:

- 프로젝트 내부 페이지
- 같은 페이지 앵커 이동

새 탭 사용 가능:

- 공식 스타벅스 페이지로 이동하는 핵심 CTA
- 포트폴리오 범위 밖의 외부 참고 페이지

### 보안 속성 기준

`target="_blank"`를 사용할 때는 다음 속성을 함께 사용한다.

- `rel="noopener noreferrer"`

또한 링크 문구나 접근 가능한 이름만 보고도 외부 이동임을 이해할 수 있어야 한다.

## 7. 접근성 정책

### 탭 이동 흐름 기준

탭 이동에는 실제로 의미 있는 요소만 포함한다.

포함 대상:

- 실제 이동 가능한 링크
- 실제 조작 가능한 버튼
- 입력 필드
- 열린 모달 내부 컨트롤
- 현재 사용할 수 있는 슬라이더 컨트롤

제외 대상:

- 닫힌 메뉴 내부 항목
- 닫힌 모달 내부 항목
- 현재 사용할 수 없는 숨겨진 슬라이드 내부 링크
- 미구현 placeholder 항목
- 장식 요소

키보드 사용자가 탭으로 이동할 때 아무 동작도 하지 않는 요소를 반복해서 만나지 않도록 해야 한다.

### 링크와 버튼의 접근 가능한 이름 기준

모든 인터랙션 요소는 접근 가능한 이름을 가져야 한다.

특히 다음 요소는 이름이 필수다.

- 아이콘만 있는 버튼
- 닫기 버튼
- 메뉴 토글 버튼
- 슬라이더 화살표 버튼
- 이미지 링크
- 반복되는 "자세히 보기" 링크

"자세히 보기"처럼 같은 문구가 반복되는 경우에는 어떤 콘텐츠의 상세 보기인지 구분할 수 있어야 한다.

### ARIA 사용 기준

ARIA는 실제 동작과 상태를 설명할 때만 사용한다.

| 속성 | 사용 기준 |
| --- | --- |
| `aria-expanded` | 메뉴, 패널, 토글처럼 펼침/접힘 상태가 있는 버튼 |
| `aria-controls` | 버튼이 실제로 제어하는 요소의 `id`가 있을 때 |
| `aria-current` | 현재 페이지 또는 현재 위치를 나타낼 때 |
| `aria-disabled` | 비활성 상태를 보조기기에 전달해야 할 때 |
| `aria-hidden` | 장식 요소 또는 의도적으로 숨긴 콘텐츠 |
| `aria-modal` | 모달 다이얼로그 맥락 |

ARIA는 잘못된 태그 사용을 보완하기 위한 수단이 아니다. 먼저 올바른 HTML 요소를 선택해야 한다.

### 닫힌 UI 내부 포커스 처리 기준

닫힌 UI 영역 내부의 포커스 가능한 요소는 키보드와 스크린리더 탐색에서 제외되어야 한다.

정책:

- 닫힌 모바일 내비게이션 내부는 포커스되지 않아야 한다.
- 닫힌 GNB 패널 내부 링크는 포커스되지 않아야 한다.
- 닫힌 모달 내부는 포커스되지 않아야 한다.
- 모달을 열면 포커스가 모달 내부로 이동해야 한다.
- 모달을 닫으면 포커스가 원래 트리거로 돌아가야 한다.
- Escape 닫기 동작은 메뉴와 모달에서 일관되게 관리한다.

### form action 처리 기준

`action="javascript:void(0)"`는 장기 정책으로 사용하지 않는다.

포트폴리오 폼 처리 기준:

- 시각 데모용 폼이면 데모 폼임을 문서화한다.
- 클라이언트 측 동작이 있다면 해당 동작을 명확히 정의한다.
- 추후 결과 페이지가 생길 예정이라면 해당 페이지가 추가될 때 연결한다.

폼 제출 의도가 있는 버튼은 `button type="submit"`을 사용할 수 있다. 다만 폼 동작을 가짜 JavaScript URL에 의존하지 않는다.

## 8. 유지보수 및 확장 정책

### 추후 내부 페이지 연결 시 규칙

새 내부 페이지가 추가되면 다음 기준으로 연결한다.

1. 해당 페이지와 직접 관련 있는 예정 항목만 `a`로 전환한다.
2. 상대 경로를 일관되게 사용한다.
3. 현재 페이지 링크에는 필요한 경우 `aria-current`를 적용한다.
4. 관련 없는 미구현 항목은 그대로 비인터랙션 상태로 둔다.
5. 실제 링크, 외부 링크, 미구현 항목이 섞일 경우 상태를 구분할 수 있게 관리한다.

### class 및 `data-*` 식별 전략

클래스는 주로 스타일 목적에 사용하고, 동작이나 정책 상태 식별은 `data-*` 속성으로 분리하는 방향이 적합하다.

사용 가능한 식별 예시:

- `data-link-type="internal"`
- `data-link-type="external"`
- `data-link-status="planned"`
- `data-action="open-menu"`
- `data-action="open-dialog"`
- `data-action="close-dialog"`

이런 기준이 있으면 나중에 링크 상태를 점검하거나 정책을 적용할 때 시각적 클래스에 의존하지 않아도 된다.

### 공통 헤더/푸터 적용 기준

`index.html`과 `signup/index.html`은 같은 헤더/푸터 정책을 공유해야 한다.

공통으로 점검할 영역:

- 헤더 로고
- 헤더 빠른 링크
- 유틸리티 메뉴
- GNB
- 검색 UI
- 푸터 메뉴 그룹
- 푸터 정책 링크
- 모바일 푸터 링크

한 페이지에서는 실제 링크이고 다른 페이지에서는 임시 링크인 상태가 생기지 않도록 주의한다.

### 중복 구조 반영 시 주의사항

헤더와 푸터가 페이지마다 중복되어 있을 경우 정책이 서로 다르게 적용될 위험이 있다.

포트폴리오 제출 전에는 두 페이지에서 다음 항목을 함께 확인한다.

- 활성 링크 기준
- 비활성 또는 예정 항목 기준
- ARIA 상태 기준
- 외부 링크 새 탭 기준
- 키보드 탭 이동 흐름

## 9. 우선순위별 적용 가이드

### 지금 바로 바꿔야 하는 것

시맨틱 구조와 포트폴리오 완성도에 직접 영향을 주는 항목이다.

- 새 `javascript:void(0)` 링크 추가 중단
- 모든 인터랙션 요소를 이동, 상태 변경, 미구현으로 분류
- 아이콘 버튼의 접근 가능한 이름 기준 확정
- 상태 변경 요소는 `button`으로 사용하는 기준 확정
- 외부 링크를 핵심 CTA 중심으로 제한
- 깨진 `aria-label` 문자열 여부 확인
- 닫힌 메뉴와 모달 내부 포커스 노출 여부 확인

### 나중에 페이지 연결 시 바꿔도 되는 것

내부 페이지가 추가될 때 처리해도 되는 항목이다.

- GNB 하위 메뉴 실제 내부 링크 연결
- 푸터 정책 및 약관 페이지 연결
- 회원가입, 아이디 찾기, 비밀번호 찾기 페이지 연결
- 검색 결과 페이지 연결
- 새 내부 페이지에 맞는 `aria-current` 적용

### 문서화만 먼저 해도 되는 것

구현 전에 기준만 먼저 정리해도 되는 항목이다.

- 포트폴리오에서 실제로 활성화할 링크 목록
- 미구현 상태로 남길 메뉴 목록
- 외부 스타벅스 링크 허용 기준
- 내부 페이지 경로 규칙
- `a`, `button`, `aria-disabled`, `data-*` 사용 기준
- 공통 헤더/푸터 점검 체크리스트

## 10. 결론

이 링크 정책은 정적 포트폴리오 프로젝트에 맞춰 설계되었다. 목표는 실제 스타벅스 사이트의 모든 경로를 재현하는 것이 아니라, 사용자가 클릭 가능한 요소의 의미를 예측할 수 있도록 만들고, 접근성과 유지보수성을 해치지 않는 구조를 유지하는 것이다. 실제 이동은 링크로, 화면 상태 변경은 버튼으로, 아직 구현되지 않은 항목은 미구현 상태로 명확히 구분한다.

정리하면 다음 한 문장으로 요약할 수 있다.

**이동하면 `a`, 상태가 바뀌면 `button`, 아직 아무 일도 하지 않으면 가짜 링크로 만들지 않는다.**
