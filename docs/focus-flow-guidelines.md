# Focus Flow Guidelines

## 목적
- 이 문서는 현재 스타벅스 스타일 정적 퍼블리싱 프로젝트에서 키보드 포커스 흐름을 어떻게 설계할지 정리한 기준 문서다.
- 목표는 `Tab` 기본 동작을 최대한 유지하면서도, 사용자가 이미 진행 중이던 맥락으로 자연스럽게 복귀하게 만드는 것이다.
- 스크롤 위치가 아니라 `직전 상호작용 맥락`을 기준으로 포커스를 설계한다.

## 핵심 원칙
- `Tab`은 기본 브라우저 흐름을 유지한다.
- 포커스를 직접 이동시키는 경우는 최소화한다.
- 포커스를 직접 이동시키는 경우는 `skip link`, `열리는 UI`, `닫힌 뒤 원래 위치로 복귀해야 하는 UI`로 제한한다.
- 스크롤 위치를 보고 포커스를 강제로 재배치하지 않는다.
- 의미 없는 `tabindex="0"`를 남발하지 않는다.
- 실제 이동은 `a`, 상태 변경과 열기/닫기는 `button`으로 구분한다.

## UX 판단 기준

### 자연스러운 경우
- 페이지 첫 진입 시 `header`부터 포커스가 시작되는 경우
- 사용자가 `메뉴 바로가기` 같은 skip link를 직접 선택한 경우
- 모바일 메뉴를 닫은 뒤 메뉴를 연 버튼으로 복귀하는 경우
- 다이얼로그를 닫은 뒤 다이얼로그를 연 버튼으로 복귀하는 경우

### 부자연스러운 경우
- 사용자가 이미 본문 CTA나 카드, 공지 영역을 보고 있는데 포커스가 다시 `header`로 돌아가는 경우
- 본문에서 연 레이어를 닫았는데 `header`로 복귀하는 경우
- 스크롤이 아래에 있다는 이유만으로 포커스를 현재 뷰포트 기준으로 강제로 옮기는 경우
- 현재 맥락과 상관없이 `Tab` 자체를 가로채는 경우

## 이 프로젝트의 설계 원칙
- 첫 진입은 `header`부터 시작해도 괜찮다.
- 이미 본문에서 상호작용을 시작한 뒤에는 그 상호작용의 시작점으로 복귀해야 한다.
- 모바일 행동형 UX가 목표이므로, 히어로와 모바일 플로우의 CTA는 읽기 순서보다 `행동 복귀 지점`으로 더 중요하다.

## 포커스를 직접 이동시켜야 하는 경우

### 1. Skip Link
- `메뉴 바로가기`
  - 목적지: 헤더 첫 메인 메뉴 버튼
- `본문 바로가기`
  - 목적지: `main` 랜드마크 자체보다 실제 본문 행동 시작점이 더 적절한지 우선 검토한다.
  - 이 프로젝트에서는 `#main_content` 또는 히어로의 첫 CTA가 후보가 될 수 있다.

### 2. 모바일 메뉴
- 열릴 때: 메뉴 내부 첫 포커스 가능 요소로 이동
- 닫을 때: 메뉴를 연 `header-toggle` 버튼으로 복귀
- 메뉴 내부 탐색: 기본 `Tab` 유지
- 선택 보조가 필요하면 `ArrowDown`처럼 명시적 키만 부분적으로 사용

### 3. 다이얼로그
- 열릴 때: 다이얼로그 내부 첫 액션 또는 닫기 버튼으로 이동
- 닫을 때: 다이얼로그를 연 원래 트리거로 복귀
- `Esc`: 닫기 지원
- `Tab`: 내부 순환

### 4. 다른 레이어형 UI
- 공지, 프로모션, 카드 영역에서 새로운 패널이나 다이얼로그가 생기면
- 닫을 때는 항상 그 UI를 연 버튼이나 링크로 복귀한다.

## 포커스를 직접 이동시키지 말아야 하는 경우
- 사용자가 일반 링크나 버튼을 따라 문서 흐름 안에서 이동하는 경우
- 사용자가 이미 현재 섹션 안에서 `Tab`으로 탐색 중인 경우
- 스크롤 위치만 내려갔다는 이유로 포커스를 본문 중간에서 시작시키는 경우
- 메가메뉴에서 단순히 `Tab`을 눌렀다는 이유만으로 하위 링크 첫 항목으로 강제 이동시키는 경우

## 현재 프로젝트 적용 기준

### Header
- 페이지 첫 진입용 포커스 시작점
- 메인 메뉴 1차 항목은 `button`
- 하위 항목은 실제 이동이면 `a`
- 메가메뉴에서는 `Tab` 기본 흐름 유지
- 필요 시 `ArrowDown`만 하위 첫 링크로 진입시키는 방식 허용

### Hero
- 데스크톱 히어로 CTA는 본문 초반 행동 시작점
- 모바일 히어로 CTA는 행동형 UX의 핵심 시작점
- 히어로에서 연 다이얼로그는 반드시 히어로 CTA로 복귀

### Order Choice Dialog
- 열기: 다이얼로그 내부 첫 액션
- 닫기: 히어로의 `앱에서 주문하기` 버튼 복귀
- 이 다이얼로그는 본문 중간 행동 흐름을 이어주는 UI로 본다

### Notice / Promotion / Mobile Flow
- 별도 레이어가 없다면 문서 흐름을 그대로 유지
- 새로운 레이어가 생기면 연 요소로 복귀
- 본문 탐색 중에는 헤더로 되돌리지 않는다

### Footer
- 문서 마지막 탐색 구간
- 추가 레이어가 없다면 기본 `Tab` 흐름 유지

## 구현 시 필요한 상태
- `lastTriggerEl`
  - 다이얼로그, 모바일 메뉴, 패널을 연 원래 트리거
- `skipTargetEl`
  - skip link 목적지
- 선택 항목: `lastMeaningfulFocusEl`
  - 본문 안에서 사용자가 마지막으로 상호작용한 핵심 요소
  - 현 단계에서는 필수는 아니지만, 복잡한 상호작용이 늘어나면 유용할 수 있다

## 실무 적용 우선순위
1. `Tab` 기본 흐름을 유지한다.
2. skip link 목적지를 실제 행동 시작점으로 정한다.
3. 모바일 메뉴 열기/닫기 복귀를 안정화한다.
4. 다이얼로그 열기/닫기 복귀를 안정화한다.
5. 본문 안에서 열린 레이어는 항상 그 섹션의 트리거로 복귀시킨다.
6. 임시 링크는 최종 단계에서 실제 링크로 교체한다.

## 하지 말아야 할 것
- 스크롤 위치를 기준으로 포커스를 재배치하는 것
- `Tab` 자체를 자주 가로채는 것
- 문맥과 상관없이 닫은 뒤 무조건 `header`로 보내는 것
- 읽기 순서를 맞추기 위해 의미 없는 포커스 정류장을 계속 추가하는 것

## 한 줄 정리
- 첫 진입일 때만 `header`부터 시작하고, 이미 무언가를 열고 닫고 있었다면 항상 그 행동을 시작한 지점으로 되돌린다.
