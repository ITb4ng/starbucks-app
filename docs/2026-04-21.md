# 2026-04-21 작업 기록

## 개요

스플래시 작업 이전 기준으로, 프로젝트의 리소스 구조와 링크/접근성 정책을 정리했다.

1. 이미지 리소스를 실제 사용 맥락별 폴더로 재배치하고, 사용하지 않는 이전 시즌 리소스는 `unused`로 분리했다.
2. 포트폴리오 범위에 맞춰 실제 링크, 준비 예정 항목, 상태 변경 버튼의 역할을 다시 구분했다.
3. 헤더, 로그인, 푸터, 프로모션, 모바일 흐름에서 접근성 흐름과 외부 링크 정책을 보정했다.

기준 커밋:

- `0b43489` - `리소스 정리 및 링크/접근성 구조 최적화`

## 주요 작업

### 1. 리소스 구조 정리
- 루트 `images` 폴더에 섞여 있던 이미지를 `common`, `footer`, `hero`, `promotion`, `reserve`, `rewards`, `store` 기준으로 재배치했다.
- 현재 화면에서 직접 사용하지 않는 과거 시즌 이미지와 레거시 슬라이드 이미지는 `images/unused`로 이동해 사용 리소스와 보관 리소스를 구분했다.
- README 배지용 SVG와 로그인 배경, 최신 히어로/프로모션 이미지를 추가해 현재 포트폴리오 화면 기준의 리소스 묶음을 명확하게 만들었다.

### 2. 링크 정책 문서화
- `docs/link-policy.md`를 추가해 포트폴리오 프로젝트에서 어떤 요소를 링크로 유지하고, 어떤 요소를 planned 상태나 버튼으로 처리할지 기준을 정리했다.
- `javascript:void(0)`와 `href="#"` 같은 임시 링크 사용을 지양하고, 실제 목적지가 없는 항목은 비인터랙션 요소 또는 명시적인 상태 요소로 관리하는 방침을 세웠다.
- 외부 링크는 포트폴리오 흐름을 보완하는 핵심 CTA에 한정하고, 평가자가 현재 페이지를 잃지 않도록 새 탭 기준을 함께 정리했다.

### 3. 인터랙션 요소 역할 재분류
- 실제 페이지 이동은 `a`, 화면 상태 변경은 `button`, 아직 구현 범위 밖인 항목은 `data-link-status="planned"` 기반의 비링크 요소로 정리했다.
- 로그인/회원가입 흐름과 헤더 유틸리티, 푸터 항목에서 클릭 가능한 것처럼 보이지만 목적지가 없는 요소를 줄이는 방향으로 마크업을 조정했다.
- 링크 정책에 맞춰 포트폴리오 핵심 흐름과 실서비스 전체 연결을 분리했다.

### 4. 접근성 흐름 보정
- 헤더 내비게이션, 검색, 로그인 화면, 푸터에서 키보드 접근과 포커스 이동 흐름을 점검했다.
- 모바일 메뉴와 데스크탑 메뉴가 같은 마크업을 공유하더라도 화면 크기별 상호작용 방식이 어색하지 않도록 CSS/JS 기준을 다듬었다.
- 데모 폼은 실제 제출이 아님을 명확히 알리고, 사용자가 기능 완료 상태로 오해하지 않도록 안내 메시지 흐름을 유지했다.

### 5. 외부 링크 정책 반영
- 스타벅스 공식 사이트로 이동하는 링크는 포트폴리오 흐름을 설명하는 데 필요한 경우에만 유지하는 방향으로 정리했다.
- 매장 찾기, 메뉴 보기, 앱/웹 주문 연결처럼 서비스 맥락 이해에 도움이 되는 CTA는 외부 링크로 유지했다.
- 푸터 정책, 회사 소개, 고객 지원, 소셜 등 실서비스 운영성 링크는 포트폴리오 범위 밖 항목으로 분류했다.

### 6. 로그인/회원가입 페이지 구조 정리
- `signup/index.html`의 헤더, 로그인 카드, 푸터 구조를 메인 페이지와 같은 정책 기준으로 맞췄다.
- 당시 작업 기준으로 `signup/join.html`이 추가되어 회원가입 화면 흐름을 분리했으나, 이후 현재 작업에서는 해당 파일이 제거되어 회원가입은 준비중 버튼 정책으로 전환되었다.
- 로그인 페이지는 실제 백엔드 제출이 없는 정적 데모라는 점을 문구와 동작으로 유지했다.
